# 日程主插件

## 选择对象与工具

| 用户要做什么 | 工具与处理方式 |
|---|---|
| 记录课程、考试、会议等占时安排 | `sched_entry`：有起止时间的日历条目 |
| 跟踪作业、报名、提交等截止或待办 | `sched_task`：有截止时间、可标记完成的任务 |
| 查询安排、找空闲、调整计划 | 查询相关日期的条目；需要待办时另查任务 |
| 把通知、图片、卡片或剪贴板内容建成日程 | 按上述语义逐项选择，不按“考试/讲座”等标题关键词机械分流 |

- 一场考试/讲座本身是条目，不自动再建任务；只有另有明确待办需求时才建任务。两者都需要时分别写入，分别报告成功与失败。
- 参数名称、枚举、必填项以当前工具 schema 为准。本 skill 补充选择与执行规则，不扩展工具能力。

## 最短执行路径

1. 从用户内容提取目标、日期时间与地点；只问影响正确写入且无法从上下文确定的缺失信息，不猜日期、截止时刻或活动时长。
2. 修改、删除、完成操作优先复用本会话已有回执的真实 `id`；否则按目标范围查询定位。同名或多个候选无法唯一匹配时先确认，不猜 id。
3. 条目要指定类别而本会话尚无当前类别列表时，用目标日期窗口的 `sched_entry(action=list)` 一次取得 `entries/categories/termStart`。已有可用列表直接复用；不需要分类时可省略 `category`，默认为 `other`。
4. 按下面的时间、类别与锁定规则直接写入；不为预判冲突先重复查表。需要去重、查空闲或比较安排时才额外查询。
5. 成功回执就是写入确认，直接回复结果；不重复查询验证。失败按回执处理，不把“已提交”当“已成功”。

## 时间、查询与教学周

- 有时刻的 `start/end/due/from/to` 使用带时区且含秒的 ISO 8601，例如 `2026-10-24T14:00:00+08:00`。相对日期以本次会话的当前日期与用户时区解释，不用旧示例充当今天；时区未知且影响结果时先确认。
- 普通条目创建必须有 `title/start/end`，且结束晚于开始；跨午夜必须写结束日的实际日期。任务创建必须有 `title/due`。
- 全天条目显式传 `all_day=true`、`start=YYYY-MM-DD`，可省略 `end`；工具按日程服务的本地时区归一为单日。不要用全天条目掩盖缺失的具体时间，或声称一次创建覆盖多天。全天改为定时条目时传 `all_day=false` 及完整 `start/end`。
- 条目查询用 `from/to` 限定目标窗口 `[from,to)`，返回所有与窗口相交的条目，包括此前开始但尚未结束的安排。查一天可用当天零点到次日零点；查自然周用周一零点到下周一零点。未给范围会返回全部条目，只有确需全量时才这样查。空列表只说明该窗口没有条目，不代表没有任务或窗口外安排。
- 任务列表默认只含未完成项，查已完成任务传 `include_completed=true`。`scope=week` 是从现在起未来 7 天，不是自然周；查指定日期/自然周时用 `scope=all` 取任务，再按 `due` 筛选。`scope=today/overdue` 使用服务当前时间。
- 条目列表、创建、更新和批量成功回执含 `week`（教学周）及 `dayOfWeek`（周一 1 至周日 7）；直接读回执，不重复推算。`week=null` 时不编造周次；周次按条目开始时间自带时区的日期计算。
- 用户只给“第 N 周周几”时，用已知 `termStart`（第一周周一）定位日期；未知则从一次条目列表取，仍为空才询问。第 N 周周一为起点加 `7×(N−1)` 天；不要把本周套到未来日期。例：起点 `2026-09-07`，第 7 周周六为 `2026-10-24`。仅按用户明确给出的周次、日期与重复规则创建，不外推未要求的安排。

## 类别、卡片字段与锁定

- 条目的 `category` 是 `categories` 返回的稳定字符串 id，按当前名称/语义匹配；不要拿显示名称、备注分类或默认预设猜 id。未知类别报错时刷新类别列表再选，找不到匹配类别用 `other`。
- 明确标为“课程/博雅课程”的活动选当前课程类别；普通讲座/体验活动不因标题自动算课程。任务的 `task_type` 是固定枚举，与可配置条目类别无关；`lecture` 仅表示讲座相关待办。
- 卡片字段：活动名 → `title`，起止 → `start/end`，场地 → `location`。教师和原始课程分类按需在 `description` 分行写 `授课教师：…\n课程类别：…`；没有的字段省略，不拼进地点，也不发明参数。
- `lock` 只防页面快捷拖动/缩放，不禁止工具改期、编辑或删除。用户指定优先；外部通知已经确定时间的课程、讲座、预约显式传 `lock=true`；自习、运动等可调整计划默认 `false`。不能只凭类别推断锁定。

## 修改、冲突与批量恢复

- 改期或改字段用 `action=update`，只传需要改变的字段；不删掉重建。省略的字段保持原值；`description/location` 传空字符串清除。
- 任务完成用 `sched_task(action=complete)`，`completed=false` 撤销完成；完成不等于删除。关联字段 `entry_id/task_id` 仅在确有对应对象及真实 id 时填写，传空字符串可解除当前字段的关联；两个字段独立，不假定自动双向同步、创建、完成或级联删除另一个对象。
- 条目写入默认 `allow_conflicts=false`。收到 `ok=false, conflicts` 表示该项未写入或未改期；说明涉及的安排与原因，取得用户允许重叠的确认后才用 `allow_conflicts=true` 重试。这是允许时间重叠，不是覆盖或删除原有安排。任务截止不会占时，不能凭没有条目冲突保证没有待办。
- 多个已明确的条目用 `action=batch_create`，每项使用条目创建字段；`allow_conflicts` 放顶层并作用于本次所有项。批量不是全有或全无：读 `okCount/total/results`，成功项有完整 `entry`，冲突失败项有 `conflicts`。仅重试失败项，不重放成功项；不要把去重等同于冲突检测。
- 工具不创建周期规则；仅将用户明确次数或起止范围的重复安排展开为具体日期后批量创建，无边界则先确认，不承诺持续自动生成。
- 没有任务批量写、条目批量修改/删除工具；按实际可用操作逐项执行，不发明 action。报错后根据明确原因修正参数；结果未知时先查目标范围定位，不盲重试造成重复。

## 能力边界与回复

- 主插件工具只操作任务和条目，不能管理类别/颜色、学期起点、提醒配置、备份或清空全部数据。此类请求引导到日程设置，不调用未暴露的服务/API，也不靠文件操作绕过。
- 普通到期提醒由插件处理；不要为它另建唤醒 Agent 的自动化任务，也不要承诺当前工具不支持的自定义提醒提前量。主插件通知依赖页面运行及通知设置，不承诺关闭页面后仍会通知。
- 日常日程操作只用日程工具。不得为查询、写入或校验而读取/搜索宿主内部存储、配置或凭据；工具缺失、回执缺必要明细时说明限制或异常，不猜数据、不用文件旁路补齐。
- 回执字段可能为 `allDay/taskType/entryId/taskId`，写入仍用工具 schema 的 `all_day/task_type/entry_id/task_id`；不要把返回对象原样回填为参数。
- 回复简洁列出已成功的标题、日期时间及必要地点；周次按回执，空字段省略。部分失败明确区分，冲突说明原因与待确认选择；不复述 JSON，不声称完成未成功的操作。
