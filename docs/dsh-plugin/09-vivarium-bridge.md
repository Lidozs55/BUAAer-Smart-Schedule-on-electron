# 09 · vivarium 桥插件设计备忘

> 桥 **⏸ 未立项**（R2：本轮不实现）。本文只固定接口边界与已定方向，供未来立项时直接开工；不含排期。
> 两方现状：`@buaaer/dsh-schedule`（主插件，含提醒子系统）· dsh-vivarium（桌宠 base 壳，独立仓库，气泡等能力仍在开发）。桥是第三件：`@buaaer/dsh-vivarium-bridge`（暂名）。

---

## 1. 职责边界：策略在主插件，表面在桥

| 插件 | 拥有 | 不拥有 |
|---|---|---|
| 主插件 | 数据（domain）、领域服务、Agent 工具、UI 面板、**提醒子系统**（提前量 Config、`ctx.schedule` 登记与撤销、投递会话、`upcomingReminders()` 派生集） | 投递表面；桌宠概念 |
| 桥 | 跨插件 UX：拖拽收纳、气泡投递、动作触发 | 数据副本；提醒策略；时序真相 |

判定规则一句话：**时序真相只有一个**（`ctx.schedule`，归主插件提醒子系统），**投递表面可以有多个**（会话消息是兜底，桌宠气泡是增强）。桌宠关闭、桥卸载，提醒仍完整可用——这是主插件与桥分立的全部理由；把镜像逻辑搬进桥会把"提醒是否可用"耦合到"桌宠是否安装"，也把稳定的策略绑上仍在变动的气泡 API 迭代节奏。

## 2. 已定方向的两条联动

### 2.1 拖拽收纳（文本/文档 → 桌宠）

拖给桌宠 → 桥新建 session，把内容作为首条消息交给 Agent（Agent 调 `buaaer_*` 工具落库）→ 桌宠播放动作「收到！」。

- 落库来源沿用 `source: 'agent'`，不新增枚举。
- 与剪贴板页（R8）同语义：都是"暂存 → 交给 Agent"；拼装提示词的约定保持一致，实现不共用。
- 拖入文件（非纯文本）桥侧只透传，不做本地解析。

### 2.2 提醒气泡（vivarium 常驻确认气泡）

主插件照常把截止镜像进 `ctx.schedule`（会话投递为兜底）；桥另取 `upcomingReminders()` 派生集驱动气泡：

- 气泡带过期时间；用户确认（"我收到了你的提醒"）自动触发 vivarium 的 accept 事件，桥只做静态确认转发，无业务判断。
- **确认 ≠ 完成**：accept 只消灭这一次气泡实例，不改 `task.completed`。气泡可带第二动作「去处理」= 打开主插件面板。
- 气泡过期未确认：不重弹，由会话投递兜底（保持简单）。

## 3. 接口约定（现在唯一要守住的）

- 桥读主插件：`inject: ['buaaerSchedule']`——`listTasks` / `subscribe` 只读够用，不给桥开写面。
- 桥读提醒面：`service.upcomingReminders()`（派生集已含各自提前量）。**提前量策略只存主插件 Config 一处**，桥不得自配一份去重算。
- 桥对 vivarium：只依赖其稳定面（拖放目标、气泡 API、动作触发）；气泡 API 未落地前不排期任何依赖它的功能。
- 桥不落业务数据：状态要么在 vivarium 侧（气泡存活期），要么派生自上两家。

## 4. 候选增强（未定，避免过度设计）

- 桌宠佩戴"今日剩余任务数 / 最近截止倒计时"徽标：只读 `listTasks`，零新表面成本，性价比最高的一条。
- 收纳两段反馈：放下瞬间「收到！」；Agent 落库完成后第二次反应（`subscribe` 到变更即可驱动）。
- 拖拽收纳改为先进剪贴板队列、由队列页统一发送：多一次人工确认、少一次误投——与 2.1 的即时发送二选一，届时按 vivarium 拖放语义定。
